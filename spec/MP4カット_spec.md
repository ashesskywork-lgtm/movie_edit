## 1. アウトカム（完了の定義）

ユーザーが単一のMP4ファイル（H.264映像＋AAC音声）を読み込み、動画プレビュー＋シークバーのドラッグ操作でカット範囲（開始秒・終了秒）を指定し、「選択範囲だけを残す」トリム処理を実行すると、フレーム単位で正確にカットされ、音声と映像が同期した状態のMP4が生成される。生成結果は実行後すぐに動画プレビューで確認でき、問題なければダウンロードできる。カット後も元動画データは保持され、範囲を変えて何度でも再カットできる（非破壊）。

## 2. スコープ

### やること（スコープ内）
- 単一MP4ファイルの読み込み（ドラッグ&ドロップ / ファイル選択）
- 動画プレビュー（video要素）＋シークバーのドラッグでカット範囲を選択するUI
- 開始秒・終了秒の数値入力とシークバー選択の双方向同期
- フレーム単位の完全カット（全フレームをデコード→トリム→再エンコード。キーフレーム単位の高速カットは採用しない）
- カットの意味は「選択範囲以外を削除（選択範囲だけを残す＝トリム）」
- 処理中の進捗表示（プログレスバー等）
- カット実行後、ダウンロード前に結果を動画プレビューで確認できる
- 非破壊処理：元動画データを保持し、カット範囲を変更して何度でも再カットできる
- 出力設定は入力（解像度・フレームレート・ビットレート）を自動継承
- ダウンロード（命名規則：`{元ファイル名}_edited.mp4`）

### やらないこと（スコープ外）
- 複数ファイルの一括読み込み・一括処理（今回は1本のみ）
- 動画結合（A+B）機能 → 独立したアウトカムのため別spec（`動画結合_spec.md`想定）として今後着手
- 音量調整・フェード・無音除去など、音声ツール由来の編集操作の動画への移植
- H.265(HEVC)等、H.264+AAC以外のコーデック対応
- 音声トラックなし／映像トラックなしなど、想定コーデック構成に合わないファイルのサポート
- 長時間（10分超）・大容量（100MB超）動画のサポート（メモリ上に全フレームを保持する設計のため対象外。将来ストリーミング処理が必要になれば再検討）
- 出力設定のカスタマイズ（解像度・ビットレートの指定変更）
- キーフレーム単位の高速カットモード（将来「高速モード」として追加検討の余地はあるが今回は対象外）

## 3. 入力と出力

- 入力：単一のMP4ファイル（H.264映像＋AAC音声）。ドラッグ&ドロップまたはファイル選択ダイアログ経由。
  - 想定サイズ感：数十秒〜数分程度の尺、数十MB程度のファイルサイズ（ゲームSE動画用途）
  - 不正・非対応入力（コーデック不一致、破損ファイル、音声/映像トラック欠如）は読み込み時にエラー表示して拒否し、ファイル一覧に追加しない
- 出力：カット後のMP4ファイル1本。コーデック・解像度・フレームレート・ビットレートは入力から自動継承。ファイル名は`{元ファイル名}_edited.mp4`（命名規則は音声ツールの`_edited.拡張子`方式を踏襲）

## 4. 境界条件・失敗系・異常系

- 未対応コーデック（H.265等）のMP4が読み込まれた → エラーメッセージを表示し、読み込みを拒否（ファイル一覧に追加しない）
- 壊れたMP4ファイルが読み込まれた → 同上、エラー表示して拒否
- 音声トラックまたは映像トラックが欠如したファイル → 同上、非対応として拒否
- カット範囲が不正（開始秒 ≥ 終了秒、範囲が動画の全長を超える、負の値等） → カット実行前にUI側でバリデーションし、実行をブロックしてエラーを示す
- カット処理に時間がかかる場合 → 進捗表示（プログレスバー等）でユーザーに処理中であることを伝える

## 5. 制約・前提

- 単一HTML完結、`file://`で直接開く運用を維持（`<script type="module">`不使用）
- 対応環境は最新のChrome / Edgeのみ（WebCodecs APIの対応状況からも実質必須の制約）
- フレームのデコード/エンコードはWebCodecs API（`VideoDecoder`/`VideoEncoder`/`AudioDecoder`/`AudioEncoder`）をネイティブ利用。追加ライブラリ不要
- MP4コンテナのmux/demuxは外部ライブラリ（書き出し：`mp4-muxer`、読み込み/解析：`mp4box.js`を想定）を埋め込み方式で使用する。CDN読み込み・外部API通信は一切禁止（2026-08-30決定、decisions.md参照）
- 数十秒〜数分・数十MB程度の動画を全フレームメモリ上に保持して処理する設計（ストリーミング処理は行わない）
- 既存の音声ツールと同様、編集操作は元データを直接破壊せず、新規データを生成する非破壊方式を踏襲する

## 6. 受け入れ基準

- [ ] 指定した開始秒・終了秒でフレーム単位の誤差内に正確にカットされている
- [ ] カット後の動画で音声と映像がズレなく同期している
- [ ] 一般的なプレイヤー（Windows標準の動画プレイヤー等、ブラウザ以外）で問題なく再生できる
- [ ] カット範囲を変更して再カットしても、元動画データが失われず何度でも実行できる
- [ ] 未対応コーデック・破損ファイルを読み込ませた際、エラー表示され一覧に追加されないことを確認できる

| タスク | 根拠（どの要件のどの型か） | 仕分け |
|---|---|---|
| 処理中の進捗表示 | 「全フレームデコード→再エンコード」は数秒〜数十秒かかりうる（アウトカムの「境界・失敗系」の型：処理が重い操作は完了未完了が分かる必要がある） | 今回やる → 2・4に反映済み |
| カット結果のプレビュー確認 | 「ダウンロード」の直前に「本当に意図通りか」を確認したいというユーザー期待（機能発火後にユーザーが次に期待する振る舞いの型） | 今回やる → 1・2に反映済み |
| 非破壊・再カット可能 | 音声ツールの既存設計方針（AudioBufferを都度新規生成し元データを破棄しない）との整合、および「一度カットしたらやり直せない」という失敗系を避けるため | 今回やる → 1・2・6に反映済み |
| 動画結合（A+B） | ユーザーからの追加要望。カット（1本を短くする）とは独立した別アウトカム（複数本を1本にする）であり、単一spec内に収めるとアウトカムが2つに増殖するため | 分割 → 別spec（`動画結合_spec.md`）としてキューに積む |
| 音声/映像トラック片方のみのファイル対応 | 「H.264映像＋AAC音声のみ対応」という入力コーデック制約の裏側（含意）：両トラックが揃っていないファイルの扱いを明示しないと実装エージェントが独自判断してしまう | 今回の対応方針を4に反映（非対応として拒否）→ スコープ外リストにも明記 |
| 出力設定のカスタマイズ（解像度/ビットレート指定） | 音声ツールの「出力サンプルレート/ビット深度指定」機能との類推で実装エージェントが「ついでに」作りがちな箇所 | 将来 → スコープ外へ明記 |
| キーフレーム単位の高速カットモード | 「カット精度と処理方式」の選択議論で出た代替案。将来的にニーズが出る可能性あり | 将来 → スコープ外へ明記 |
