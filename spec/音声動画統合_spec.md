## 1. アウトカム（完了の定義）

`C:\動画ファイルエディタ`のindex.html 1ファイルに、`C:\音声ファイルエディタ`（WAV編集ツール）の音声編集7機能（カット・音量調整・ノーマライズ・フェードイン/アウト・無音除去・複数ファイル結合・リバース）を移植し、既存の共有ファイル一覧（files配列+activeEntry方式）でWAVファイルとMP4ファイルを同じ一覧に読み込める状態にする。一覧でファイルを選択すると、その型（WAV/MP4）に応じて音声編集パネルまたは動画編集パネルが切り替え表示され、型ごとの編集操作（音声7機能／動画のカット・結合）を実行できる。処理はアプリ全体で同時に1操作のみ（型を問わず完全排他）。編集結果はそれぞれの命名規則（WAV: `_edited.wav`/`_merged.wav`、MP4: `_edited.mp4`/`_merged.mp4`）でダウンロードでき、非破壊で元ファイルは保持され、結果はファイル一覧へ新規追加されて再編集・再結合の入力にできる。画面タイトル・ツール名は「動画・音声編集ツール」に変更する。

## 2. スコープ

### やること（スコープ内）
- `C:\動画ファイルエディタ`のindex.htmlを土台にする（音声ファイルエディタ側は改修しない）
- 音声ファイルエディタの7機能（カット・音量調整・ノーマライズ・フェードイン/アウト・無音除去・複数ファイル結合・リバース）のロジック・UIを移植
- ファイル入力（`<input type="file">`のaccept属性、D&D処理）を.wav/.mp4両方に対応するよう拡張
- 共有ファイル一覧に型（WAV/MP4）バッジを追加表示（既存の処理由来バッジ「カット結果」「結合結果」等と併記）
- 選択中ファイルの型に応じて音声編集パネル/動画編集パネルを切り替え表示（未選択時は両方非表示、既存の「未選択時」表示を踏襲）
- 結合（音声側・動画側）は同型のみ許可。型混在チェック時は結合実行ボタンをブロックしエラー表示
- 処理排他制御をアプリ全体・型問わず完全排他に統一（音声処理中は動画操作ボタンも無効化、逆も同様）
- 画面タイトル・ツール名を「動画・音声編集ツール」に変更
- CLAUDE.mdを更新し、統合後のスコープ・技術スタック（音声処理はWeb Audio API、動画処理はWebCodecs API+埋め込みライブラリ）を反映

### やらないこと（スコープ外）
- 動画からの音声抽出（WAV書き出し）：将来別アウトカムとして着手（tasks.md記載済み、今回のspecには含めない）
- 動画への音声差し替え：将来別アウトカムとして着手（tasks.md記載済み、今回のspecには含めない）
- WAVとMP4をまたいだ結合（音声+動画を1つに結合する等）：技術的に意味をなさないため対象外、将来検討もなし
- ファイル一覧の型別フィルタ・並べ替え等の新規UI：今回は型バッジ表示のみ
- `C:\音声ファイルエディタ`側への変更：手を付けず現状のまま残す（README等への移行先の追記もしない）
- Undo/Redo・ダークモード・ショートカット一覧・編集履歴ログ等、音声ツール由来の元々保留中だった追加機能：今回も保留のまま
- サンプルレート/ビット深度指定、モノラル/ステレオ変換等の出力設定：今回も保留のまま

## 3. 入力と出力

- 入力：ドラッグ&ドロップ・複数ファイル選択で、拡張子.wavまたは.mp4のファイルを受け付ける。それ以外の拡張子は読み込み時にエラー表示・一覧非追加（既存のMP4側の非対応コーデック拒否と同様の扱い）
- 出力：型ごとの既存命名規則を維持する
  - WAV：`{元ファイル名}_edited.wav` / `{1本目}_merged.wav`（重複時は連番付与、既存ロジック踏襲）
  - MP4：`{元ファイル名}_edited.mp4` / `{1本目}_merged.mp4`（重複時は連番付与、既存ロジック踏襲）

## 4. 境界条件・失敗系・異常系

- 型混在（WAV+MP4）選択で結合実行操作をした場合 → 結合実行ボタンをdisabled化し、エラーメッセージを表示する（例：「結合は同じ形式（WAVまたはMP4）同士のみ実行できます」）。WAV同士・MP4同士の結合は従来通り可能
- 音声処理（カット・音量調整・ノーマライズ・フェード・無音除去・結合・リバースのいずれか）実行中に動画のカット/結合ボタンを押そうとした場合（またはその逆） → 型を問わず全操作ボタンをdisabled化し実行不可とする（既存の動画カット/結合の相互排他を、音声処理を含めた完全排他へ拡張）
- 拡張子.wav/.mp4だが中身が非対応（例：wavヘッダ破損、mp4がH.264+AAC以外・トラック欠如）→ 各ツールの既存バリデーション・エラーメッセージをそのまま踏襲し、一覧に追加しない
- ファイル一覧が空の状態 → 音声編集パネル・動画編集パネルともに非表示
- 音声ファイルと動画ファイルが同名（拡張子違い）で一覧に存在する場合 → 型バッジで区別され共存可能。ダウンロード時のファイル名は元の拡張子ベースで独立するため衝突しない

## 5. 制約・前提

- 既存CLAUDE.mdの規約（camelCase/UPPER_SNAKE_CASE、async/await必須（Promiseチェーン禁止）、AudioContextはアプリ全体で1つだけ生成し使い回す、秒数は小数点3桁まで、`file://`運用のため`<script type="module">`禁止、単一HTML完結）をすべて継承する
- 依存ゼロ原則の例外は引き続きMP4コンテナ処理ライブラリ（mp4box.js/mp4-muxer）のみ。音声側から移植するロジックは元々依存ゼロなので変更なし
- 音声側の波形描画・プレビュー再生に使う`AudioContext`（リアルタイム再生用）と、動画側の結合機能が音声リサンプリングに使う`OfflineAudioContext`（オフライン変換用）は別物であり、後者は既存通り都度生成でよい。CLAUDE.mdの「AudioContextは1つだけ生成し使い回す」の対象は前者（リアルタイム再生用の`AudioContext`）である
- JS識別子（関数名・グローバル変数名）の衝突リスクに注意する。2つの独立実装を1ファイルへ統合する際、同名の関数・変数（例：`renderFileList`等、命名が重複しそうな箇所）があれば実装時にリネームして解消すること
- 対応ブラウザは引き続きChrome/Edge最新のみ（Safari/Firefox非対応）
- ファイルサイズ想定は各ツールの既存実績を踏襲（動画：数十秒〜数分・数十MB程度、音声：音声ツール実績相当）

## 6. 受け入れ基準

- [ ] WAVファイルを読み込むと共有一覧に「WAV」バッジ付きで追加される
- [ ] MP4ファイルを読み込むと共有一覧に「MP4」バッジ付きで追加される
- [ ] WAVファイルを選択すると音声編集パネル（カット・音量調整・ノーマライズ・フェード・無音除去・結合・リバース）が表示され、動画編集パネルは非表示になる
- [ ] MP4ファイルを選択すると動画編集パネル（カット・結合）が表示され、音声編集パネルは非表示になる
- [ ] 音声7機能が、音声ファイルエディタ単体時と同等に動作する（カット・音量調整・ノーマライズ・フェード・無音除去・結合・リバースそれぞれで正しい結果が得られることをブラウザ実機確認）
- [ ] 動画のカット・結合機能が、統合前と同等に動作する（既存の受け入れ基準に対する回帰がないことをブラウザ実機確認）
- [ ] WAV+MP4混在選択で結合を実行しようとするとブロックされ、エラーメッセージが表示される
- [ ] 音声処理中は動画のカット/結合ボタンが無効化され、動画処理中は音声の各操作ボタンが無効化される（型を問わない完全排他）
- [ ] 非対応拡張子（.wav/.mp4以外）を読み込むとエラー表示され一覧に追加されない
- [ ] ダウンロードファイル名が型ごとの命名規則通り（WAV: `_edited.wav`/`_merged.wav`、MP4: `_edited.mp4`/`_merged.mp4`）
- [ ] 画面タイトルが「動画・音声編集ツール」に変わっている
- [ ] 非破壊：音声・動画それぞれ、編集後も元ファイルが一覧に残り再編集・再結合できる
