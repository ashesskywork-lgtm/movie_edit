## 1. アウトカム（完了の定義）

ユーザーは複数のMP4ファイル（読み込んだ元ファイル・カット機能で生成したカット結果を含む）を共有のファイル一覧で管理でき、一覧から2本以上を選んで結合順序（上下ボタンでの並び替え）を指定し「結合実行」すると、解像度・フレームレート・音声形式（サンプルレート・チャンネル数）が1本目の設定に自動的に揃えられた上で1本のMP4に結合される。結合処理中は進捗表示され、途中でキャンセルもできる。結合完了後はダウンロード前に結果を動画プレビューで確認でき、結合結果はファイル一覧に新規追加されて、さらに別のカット・結合の入力としても使える。結合後も元のファイル一覧は保持され（非破壊）、順序を変えて何度でも再結合できる。

## 2. スコープ

### やること（スコープ内）
- 複数のMP4ファイルの読み込み・共有ファイル一覧での管理（**カット機能のUIも「単一ファイル完結」から「共有ファイル一覧から対象を選ぶ」方式へ改修する**。一覧には読み込んだ元ファイルと、カット・結合で生成した結果ファイルの両方が並び、どちらもカット・結合両方の入力として選択できる）
- ファイル一覧から2本以上（可変本数、上限なし）を選択し、上下ボタンで結合順序を並び替える操作
- 結合対象の動画間で解像度・フレームレートが異なる場合、1本目の設定に自動変換してから結合（エラーにしない）
- 結合対象の動画間で音声形式（サンプルレート・チャンネル数）が異なる場合も、1本目の設定に自動変換してから結合（エラーにしない）
- 結合中の進捗表示（プログレスバー等）
- 結合処理中のキャンセル機能（キャンセルすると処理を中断し、部分的な結果は破棄してメモリを解放する）
- 結合実行後、ダウンロード前に結果を動画プレビューで確認できる
- 非破壊処理：結合を実行しても元のファイル一覧（元ファイル・既存の結果ファイル）は保持され、順序を変えて何度でも再結合できる
- 結合結果はファイル一覧に新規追加され、以後の別のカット・結合操作の入力として選択できる（結合結果をさらに結合する、結合結果をカットする、といった連鎖が自然にできる）
- ダウンロード（命名規則：`{結合順序の1本目のファイル名}_merged.mp4`）
- 入力動画のコーデック制限はカット機能と同じ（H.264映像＋AAC音声のみ。それ以外は読み込み時エラーで拒否）

### やらないこと（スコープ外）
- 結合の切り替わり部分へのトランジション効果（クロスフェード等）
- 結合対象が1本以下の状態での結合実行（エラー表示でブロックする。0本・1本どちらも同様に扱う）
- H.264+AAC以外のコーデック（H.265等）、音声/映像トラック片方欠如、破損ファイルのサポート（読み込み時エラーで拒否。カット機能と同じ方針）
- ファイル一覧に読み込めるファイル数の上限バリデーション（実際の想定規模内で動けばよく、明示的な上限チェックは設けない）
- カット機能自体への処理中キャンセル機能の追加（今回のスコープは結合機能のみ。カット機能への遡及対応は別途検討）
- 出力設定のカスタマイズ（解像度・ビットレート等をユーザーが指定変更する機能。あくまで「1本目に自動的に揃える」のみ）
- 長時間・大容量動画のサポート（カット機能と同じ制約。全フレームをメモリ上に保持する設計のため、数十秒〜数分・数十MB程度、合計数本程度を想定規模とする）

## 3. 入力と出力

- 入力：ファイル一覧から選択した2本以上のMP4（H.264映像＋AAC音声）。選択順序はユーザーが上下ボタンで並び替え可能。
  - 想定サイズ感：1本あたり数十秒〜数分程度の尺・数十MB程度のファイルサイズ、合計で数本程度（ゲームSE動画・AI生成動画用途。カット機能と同等の想定規模）
  - 不正・非対応入力（コーデック不一致、破損ファイル、音声/映像トラック欠如）は読み込み時にエラー表示して拒否し、ファイル一覧に追加しない（カット機能と同じ方針）
- 出力：結合後のMP4ファイル1本。解像度・フレームレート・音声形式（サンプルレート・チャンネル数）は、結合順序の1本目の設定に自動的に揃える。ファイル名は`{1本目のファイル名}_merged.mp4`

## 4. 境界条件・失敗系・異常系

- 未対応コーデック（H.265等）のMP4が読み込まれた → エラーメッセージを表示し、読み込みを拒否（ファイル一覧に追加しない）
- 壊れたMP4ファイルが読み込まれた → 同上、エラー表示して拒否
- 音声トラックまたは映像トラックが欠如したファイル → 同上、非対応として拒否
- 結合対象の選択が1本以下の状態で「結合実行」を押した → 実行前バリデーションでブロックし、エラーメッセージを表示（「2本以上選択してください」等）
- 結合対象の動画間で解像度・フレームレート・音声形式（サンプルレート・チャンネル数）が異なる → エラーにせず、1本目の設定に自動変換してから結合する
- 結合処理に時間がかかる場合 → 進捗表示（プログレスバー等）でユーザーに処理中であることを伝える
- 結合処理中にユーザーがキャンセルを実行した場合 → 処理を中断し、それまでに生成された部分的なデータ（デコード済みフレーム等）を解放する。中断後は結合実行前の状態に戻り、ダウンロード可能な結果は生成されない

## 5. 制約・前提

- 単一HTML完結、`file://`で直接開く運用を維持（`<script type="module">`不使用）
- 対応環境は最新のChrome / Edgeのみ（WebCodecs APIの対応状況からも実質必須の制約）
- フレームのデコード/エンコードはWebCodecs API（`VideoDecoder`/`VideoEncoder`/`AudioDecoder`/`AudioEncoder`）をネイティブ利用。追加ライブラリ不要
- MP4コンテナのmux/demuxは既に埋め込み済みの`mp4box.js`（demux）・`mp4-muxer`（mux）をそのまま使う。新規ライブラリの追加は行わない
- MP4カット機能の実装で得られた以下の知見・対策を踏襲する：
  - `VideoDecoder.configure()`には`hardwareAcceleration: 'prefer-software'`を指定する（ハードウェアデコーダのサーフェスプール上限によるデッドロックを避けるため）
  - `AudioEncoder`のビットレート・サンプルレートは、入力の実測値をそのまま使わず、ブラウザが受理する値へ動的検証・フォールバックするロジック（既存の`resolveAudioEncodeConfig`相当）を再利用・拡張する
- 数十秒〜数分・数十MB程度の動画を合計数本、全フレームメモリ上に保持して処理する設計（ストリーミング処理は行わない）
- 既存のカット機能と同様、処理は元データを直接破壊せず、新規データ（結合結果）を生成する非破壊方式を踏襲する
- カット機能のUI（現状「単一ファイル読み込み→即編集」という1ファイル完結の構造）を、「複数ファイルを共有一覧で管理し、一覧から対象を選んでカット・結合を実行する」構造へ改修する必要がある（既存カットUIへの変更を伴う）

## 6. 受け入れ基準

- [ ] 複数のMP4ファイルを読み込むと、共有ファイル一覧に反映される
- [ ] カット機能で生成したカット結果も、同じファイル一覧に反映される
- [ ] ファイル一覧から2本以上を選択し、上下ボタンで順序を指定して「結合実行」すると、進捗表示→結果プレビュー→ダウンロードの一連の流れが動作する
- [ ] 解像度・フレームレート・音声形式（サンプルレート・チャンネル数）が異なる動画同士でも、1本目の設定に自動的に揃えられて結合され、映像・音声がズレなく同期する
- [ ] 結合対象が1本以下の状態で結合実行するとエラーでブロックされる
- [ ] 未対応コーデック・破損ファイルを読み込ませた際、エラー表示され一覧に追加されないことを確認できる
- [ ] 結合処理中にキャンセルを実行すると、処理が中断され、部分的な結果はダウンロードできない状態になる
- [ ] 結合後も元のファイル一覧（元ファイル・既存の結果ファイル）は保持され、順序を変えて再結合できる
- [ ] 結合結果がファイル一覧に新規追加され、さらに別のカット・結合の入力として選択できる
- [ ] ダウンロードファイル名が`{1本目のファイル名}_merged.mp4`の命名規則通りになっている
